# Known limitations and next priorities

1. **PostgreSQL/Compose execution unverified on this host.** Docker and PostgreSQL executables are absent. The configured relational schema, PostgreSQL driver, migrations, image build and volumes are provided. Run `docker compose up --build` on a Docker-enabled machine, then repeat the workflow and test NUMERIC persistence there. SQLite verification does not establish PostgreSQL behavior.
2. **Live extraction unverified.** No credentials were provided and no paid API calls were made. Set server-side credentials, upload a fictional sample and explicitly initiate extraction. Validate provider/schema compatibility and separately measure field extraction accuracy and latency. The manual/fixture fallback is tested.
3. **Record import scope.** Seeded reviews have relational holdings, mutations and history. A fresh manual upload starts without authoritative supporting records and therefore returns insufficient information after confirmation. The UI does not yet let officers import a structured holding/mutation/history set. Add a validated, provenance-preserving record import workflow next; never infer it from a deed image.
4. **Unresolved-field requests.** Cases with unreadable critical identifiers cannot be analyzed or receive an analysis-linked decision until resolved. A dedicated pre-analysis request-for-information event is a useful next workflow addition.
5. **Geographic scope.** 64 districts and 495 upazilas from a dated official directory are imported, but only three verified mouzas. The directory's 495/500 header discrepancy is unresolved; national completeness is not claimed. Empty mouza states are explicit. Verification used authoritative Gazette text; Gazette screenshot retrieval failed. JL/official codes are omitted. English names are human transliterations. A dated complete mouza register and domain review are needed for further coverage.
6. **Rule boundaries.** No geometry, cadastral map alignment, real government lookup, joint-ownership allocation, inheritance, subdivision or automatic cross-survey matching. Ambiguity requires manual review. No identity inference from similar names.
7. **Prototype security.** Local reviewer accounts and ownership isolation, not SSO, role administration, MFA or a production security audit. No antivirus, distributed login throttle, tamper-proof audit storage, backup automation or multi-node deployment. Uploads must remain fictional. Loopback use only until hardened.
8. **Evidence and reports.** Source exhibits remain in their original language. Notes are never machine-translated. The report prints both interface languages but source labels, references and user notes remain original. PDF validation does not make hostile PDFs safe for arbitrary production use.
9. **UI maintainability.** The functional React view is concentrated in one file for this vertical slice. Extract components as further review workflows are added. Typed API response models and generated frontend API types are a next code-quality improvement.
10. **Audit and storage.** Application APIs only append audit history; administrators can alter the database. Demo reset deletes database rows but intentionally leaves uploaded/generated files in the runtime directory. Configure retention before any broader deployment.

No nationwide accuracy, calibrated fraud probability, legal certification, government endorsement or public deployment is claimed.
